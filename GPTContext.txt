GAME LOOP:
    let lastTime = null;

    function gameLoop(timestamp) {
        if (lastTime === null) {
            lastTime = timestamp;
        }

        const deltaTime = (timestamp - lastTime) / 1000;
        lastTime = timestamp;

        game.update(deltaTime);
        game.draw();

        requestAnimationFrame(gameLoop);
    }

    requestAnimationFrame(gameLoop);

IMPORTANT:
- We use requestAnimationFrame.
- We calculate deltaTime in seconds.
- Movement uses speed * deltaTime so it is frame-rate independent.
- We learned the basic loop:
      INPUT → UPDATE → DRAW → next frame

MATH UTILITY:
    function clamp(value, min, max) {
        return Math.max(min, Math.min(max, value));
    }

We use clamp to keep objects inside boundaries.

1. CANVAS BASICS
- <canvas> is a drawing surface.
- getContext("2d") gives the 2D drawing context.
- ctx.fillRect(x, y, width, height)
- fillStyle controls drawing color.
- clearRect() clears the previous frame.
- Canvas coordinates begin at top-left:
      (0, 0)
      x increases right
      y increases downward.

Unity mental model:
    Canvas drawing surface ≈ low-level rendering surface
    ctx ≈ drawing API

2. GAME LOOP
Concept:
    update game state, then render it every frame.

Pattern:
    game loop

Structure:
    update(deltaTime)
    draw()
    requestAnimationFrame(gameLoop)

3. INPUT STATE
Instead of moving directly inside keydown:
    keys[event.code] = true/false

Then update reads the current input state.

Pattern:
    input state / polling-style input

4. DELTA TIME
We learned why:
    playerX += 5
is bad because movement depends on FPS.

Instead:
    playerX += speed * deltaTime

This produces pixels-per-second style movement.

5. DIRECTION + VELOCITY
Initially input directly changed position.
We changed architecture to:

    Keyboard
       ↓
    directionX/Y
       ↓
    normalize
       ↓
    velocityX/Y
       ↓
    position
       ↓
    clamp
       ↓
    draw

Direction:
    right = (1,0)
    left  = (-1,0)
    up    = (0,-1)
    down  = (0,1)

6. NORMALIZATION
We learned diagonal movement is faster if direction = (1,1).

Normalize:
    length = sqrt(x*x + y*y)
    x /= length
    y /= length

This makes movement speed consistent in all directions.

Concept:
    vector normalization

We learned not to splice while iterating forward with for...of.

Concept:

13. AABB COLLISION
Added GameObject.isColliding(other):

    isColliding(other) {
        const isOverlappingX =
            this.x < other.x + other.width &&
            this.x + this.width > other.x;

        const isOverlappingY =
            this.y < other.y + other.height &&
            this.y + this.height > other.y;

        return isOverlappingX && isOverlappingY;
    }

Concept:
    AABB (Axis-Aligned Bounding Box) collision

Important:
- Collision needs overlap on BOTH X and Y.
- This method belongs in GameObject because Player, Enemy, Bullet can all collide.

14. ENEMY HEALTH / DAMAGE
Enemy has:
    this.health = 3;
    this.isDead = false;

Enemy:
    takeDamage(damage) {
        if (this.damageTimer > 0) {
            return;
        }

        this.health -= damage;
        this.health = clamp(this.health, 0, 3);

        this.damageTimer = this.damageCooldown;

        if (this.health <= 0) {
            this.isDead = true;
        }
    }

Enemy damage cooldown:
    this.damageCooldown = 0.5;
    this.damageTimer = 0;

update():
    if (this.damageTimer > 0) {
        this.damageTimer -= deltaTime;
    }

Concept:
    cooldown/timer-based interaction

15. BULLETS
Bullet extends GameObject.

Current concept:
    bullet moves right
    bullet dies when outside canvas

Basic structure:
    class Bullet extends GameObject {
        constructor(x, y) {
            super(x, y, 10, 10);

            this.speed = 500;
            this.isDead = false;
        }

        update(deltaTime) {
            this.x += this.speed * deltaTime;

            if (this.x > canvas.width) {
                this.isDead = true;
            }
        }

        draw(ctx) {
            ctx.fillStyle = "yellow";
            ctx.fillRect(
                this.x,
                this.y,
                this.width,
                this.height
            );
        }
    }

16. BULLET ↔ ENEMY COLLISION
Game checks:
    for each bullet
        for each enemy
            if collision:
                enemy.takeDamage(1)
                bullet.isDead = true
                break

The break is important so one bullet doesn't damage multiple enemies in the same frame.

22. GAME CLASS / OWNERSHIP
We moved global game state into:

    class Game {
        constructor() {
            this.player = new Player(100, 100);

            this.gameState = "start";

            this.enemySpawnTimer = 0;
            this.enemySpawnCooldown = 1;
        }

        spawnEnemy() { ... }

        update(deltaTime) { ... }

        draw() { ... }

        restart() { ... }
    }

Then:

    const game = new Game();

Game loop:
    game.update(deltaTime);
    game.draw();

Concept:
    central game/world manager
    ownership of runtime game state

23. PLAYER → GAME COMMUNICATION
Important architectural issue:
Player should NOT directly manipulate:
    game.bullets
    global bullets array

We changed shooting concept to return an action.

Player.update() now creates:
    const actions = [];

When shooting:
    actions.push({
        type: "shoot",
        bullet: this.shoot()
    });

At end:
    return actions;

Game receives:
    const actions = this.player.update(deltaTime);

    for (const action of actions) {
        if (action.type === "shoot") {
            this.bullets.push(action.bullet);
        }
    }

Concept:
    object communication / event-action communication
    lightweight Command/Event-style pattern

Why useful:
    Player doesn't need to know how Game stores bullets.
    Game remains the owner of world collections.
